# 小狐狸主題：原生驗證

目前環境為 Linux，以下 UIKit 測試與效能量測**尚未執行**。Node／瀏覽器預覽檢查不代表 iPhone 已驗證。

## 在 Mac 執行

使用與打包 workflow 相同的 Xcode 26 SDK。於根目錄執行 `xcodegen generate`，開啟產生的 `StarKeyboard.xcodeproj`，選擇 `StarKeyboardThemeTests` scheme 與 iPhone 模擬器，執行 Test（⌘U）。命令列可用：

```sh
xcodebuild test -project StarKeyboard.xcodeproj -scheme StarKeyboardThemeTests \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -resultBundlePath /tmp/fox-letter-tests.xcresult \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO
```

模擬器名稱需對應本機已安裝裝置；結果路徑需尚未存在。CI 會自動選擇可用的 iOS 26 iPhone 模擬器。

13 項測試尚待執行，本輪已擴充素材載入、縮圖尺寸、圖層與共用 CGImage 的檢查，涵蓋：

- 真正 `KeyLayouts` 的六種模式、四種頁面、注音欄數與地球鍵；窄螢幕及橫向尺寸。
- 手寫側欄、大小寫重用、換行圖示／搜尋文字切換、一般主題切回與個人設定保留。
- 500 次按下／放開及游標淡化後，按鍵命中區、插畫物件、圖層數量與路徑不變。
- 同配件換毛色／文字保留幾何；不同尺寸及配件使用正確快取；矮鍵與個人空白鍵圖片不殘留配件。
- 移除按鍵後可釋放視圖，快取不持有按鍵；1,000 次按壓回饋的時間與記憶體量測。

CI 的 `fox-letter-tests` artifact 保存 `.xcresult` 與測試日誌，即使測試失敗也會嘗試上傳。用 Xcode 開啟 `.xcresult` 查看失敗位置與效能數字。第一次量測用來建立基準；目前未設定跨機器的固定毫秒門檻，也沒有已通過的效能數字。

效能測試先完成排版並關閉 UIKit 動畫，隔離按壓更新的主執行緒成本。它不包含實際觸控、畫面合成、GIF 或動畫播放，這些需用下方真機流程檢查。

## iPhone 驗收記錄

先填機型、iOS 版本、build／commit、一般主題名稱，以及是否開啟「減少動態效果」。每項記錄通過／失敗與重現步驟，不以模擬器時間推論真機表現。

| 操作 | 檢查內容 | 狀態 |
|---|---|---|
| 一般主題 → 小狐狸 → 一般主題，重複 10 次 | 照片、造型、質感、字體、尺寸設定保留；無殘留插畫或玻璃 | 待驗證 |
| 六種模式、123／符號／數字盤、注音兩種欄數、Shift | 字與提示字清楚、動作正確；鍵盤高度與間距極值不裁切 | 待驗證 |
| 連打、長按提示字、滑動修正、連續刪除、英文滑行 | 無遺失操作、卡鍵或明顯卡頓 | 待驗證 |
| 空白鍵拖曳游標後放開 | 字面／插畫透明度恢復；五官與裝飾位置不跳動 | 待驗證 |
| 手寫、候選字、表情、顏文字、剪貼簿、設定面板 | 按鍵與內容可讀、選取與切換正常 | 待驗證 |
| 自選空白鍵靜態圖／GIF，清除後再套回 | 圖片等比例、GIF 正常；圖片覆蓋時收起信封，清除後恢復 | 待驗證 |
| 每種既有動畫；開啟／關閉「減少動態效果」 | 動畫符合設定，減少動態效果時不縮放／彈跳 | 待驗證 |
| 直向／橫向、關閉鍵盤再開啟 | 寬鍵五官不被拉長，系統容器與地球區無新增遮擋 | 待驗證 |

效能另以同一支手機、相同文字與設定比較一般主題和小狐狸主題。先暖機，再連續輸入 2 分鐘、反覆切換頁面／主題 20 次；用 Instruments 的 Time Profiler／Allocations 記錄主執行緒耗時與存活配置。完成後靜置並再做同一輪，檢查是否持續增加存活的按鍵／圖層，並記錄 extension 重載或卡頓。水彩素材最長邊縮至 768 px、共用 CGImage、快取成本設定為 8 MiB；向量 fallback 路徑快取保留 64 組限制，可在記憶體壓力時釋放；真機數據仍需實測。
